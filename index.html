SchooledUp

Information processing / Software

Problem and product
Course information arrives across documents, slides, recordings and email. I created SchooledUp to bring those inputs into one student workspace: extract deadlines and course information, route them to the right course, and organize them as tasks and source-linked notes.
Creator and product developer
I directed product design and full-stack implementation using AI coding tools. My work spans the Next.js interface, Python/FastAPI backend, course routing and review workflow, with Supabase for application data, authentication and file storage.
Workflow and design choice
Documents, transcripts and email → extracted fields → course routing → source-linked notes and tasks. Results appear in the workspace after processing. Students can review the source and correct the information afterward.
Illustrative example · fictional data
Input: “STAT-DEMO: Problem set 2 is due October 14, 2026.” Intended output: a task named “Problem set 2,” assigned to STAT-DEMO with an October 14 deadline and a link to its source. This describes the workflow, not a measured extraction result.
Limits and corrections
Ambiguous dates, missing context or mixed-course material can lead to an incorrect deadline or course assignment. Students can inspect the linked source and edit results through the GUI. Automated output still needs judgment.

Pathfinding & game navigation

Algorithms / Interactive systems

A platformer navigation experiment: build a level, then watch an agent find a route with A*, using jumps, gravity, and collisions. Originally built in Python with py5 and adapted for the browser so you can edit the level and explore the graph yourself.

My contribution
The original Python/py5 project was designed and hand-coded entirely by me, including graph generation, A* pathfinding, agent behaviour, and the interactive editor. The browser adaptation was developed with AI assistance.
Question, inputs and method
Can an agent reach a goal using walks, jumps and drops? Platform tiles and start/goal positions become a navigation graph. A* searches the connections, and the agent attempts the route under gravity and collision rules.
Output and limitations
The playground displays the graph, route and agent movement. Link costs and jump reachability are approximations, so a route is not guaranteed to be shortest or physically completable on every custom level.

Physics simulations

Soft bodies / Collisions / Constraints

A soft-body simulation built from linked points: it falls, deforms, and pushes back toward its original area. Built in Python with py5, with mouse interaction to pull it around.

Related experiments
Ball physics on uneven terrain, then a simple car made by linking two balls together and adding directional controls. Built in Processing’s Python mode.
Model and output
How do linked points respond to gravity and a mouse drag? Initial positions, gravity, damping and distance constraints drive a Verlet simulation. Area restoration gives the soft body its shape; a distance constraint links the car’s wheels. The output is an interactive view of deformation and motion.
My contribution and limitations
I independently programmed the original Python/py5 and Processing experiments. The JavaScript/Canvas adaptations are AI-assisted. These are simplified numerical models, not calibrated physical measurements. Terrain and dragging differ from the originals, and steep slopes can exceed the car’s driving force.
